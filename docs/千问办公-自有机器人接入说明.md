# 自有 AI 机器人接入千问办公（QwenWork）说明文档

> 编制日期：2026-11-05
> 信息来源：千问办公官方帮助中心，全部链接均为公开可访问地址，见附录 A
> 适用对象：已有自研 AI 机器人 / MCP 服务 / 本地工具链，希望让千问办公能够调用其能力的开发者与业务用户

---

## 一、先厘清两条方向完全相反的链路

大多数人卡在这一步：把「让机器人接进千问办公」和「让千问办公接进 IM」混为一谈。这是两套独立机制，配置入口、技术前提、能达到的效果都不一样。

| | 方向 A：你的能力 → 给千问办公用 | 方向 B：千问办公 → 出现在你的 IM 里 |
|---|---|---|
| 机制名称 | **连接器（自定义 MCP 服务）** | **IM 频道** |
| 谁调用谁 | 千问办公作为 MCP 客户端，调用你的 MCP 服务端 | 你在钉钉/飞书/微信里 @ 机器人，它驱动千问办公 |
| 你的机器人角色 | 被调用的「工具」 | 千问办公本身就是一个 IM 机器人 |
| 配置入口 | 桌面端左侧导航「扩展」→「连接器」→「+ 添加」 | 桌面端「IM 频道」页面（钉钉/飞书/Lark/微信/企业微信/Slack/WhatsApp） |
| 典型用途 | 查你自研系统的业务数据、调用你封装的算法、操作本地工具 | 出差路上用手机指挥公司电脑上的千问办公干活 |

**结论：想让"你自己的机器人"变成千问办公的能力，只有 方向 A（MCP 连接器）这一条官方通路。** 方向 B 无法挂接第三方机器人——它绑定的是千问办公自己的官方 IM 机器人。

## 二、主路径：把你的机器人注册为「自定义 MCP 服务」

### 2.1 前提：你的机器人必须说 MCP 协议

MCP（Model Context Protocol）是一套开放协议，官方文档的比喻是"AI 世界的 USB 接口"。千问办公只认三种服务器类型，你的机器人必须落进其中一种：

| 服务器类型 | 传输方式 | 你的机器人需要满足什么 |
|---|---|---|
| **Streamable HTTP**（官方推荐） | 远程 URL，HTTP 双向流 | 提供一个公网可达的 `/mcp` 端点，实现 Streamable HTTP 协议 |
| **SSE** | 远程 URL，Server-Sent Events | 同上，但走较老的 SSE 传输。新服务建议直接用 Streamable HTTP |
| **STDIO** | 本机命令行拉起子进程 | 你的机器人能用一条命令在本机启动（`npx` / `uvx` / `python` / `docker run`），通过标准输入输出交换 JSON-RPC |

> 关键提示：**STDIO 类型不需要公网 IP、不需要暴露端口、不需要内网穿透。**
> 桌面端就在你的电脑上，它直接在你的机器上 fork 一个本地进程。这对"机器人部署在本地"的场景是最省事的方案。

### 2.2 如果你的机器人只是普通 HTTP API（不是 MCP）

协议层不兼容，千问办公无法直接调用，需要在你的机器人外面包一层 MCP Server 做适配。两条路：

1. **官方 SDK 封装**：用 `@modelcontextprotocol/sdk`（TS）或 `mcp` / `fastmcp`（Python）把已有接口逐个暴露成 MCP tool，进程内直接调你的机器人逻辑。
2. **用转换工具生成**：如果已经有 OpenAPI / Swagger / Postman 集合或 curl 命令，可以先把它封装成 MCP server 再注册到千问办公，避免逐个手写 tool 定义。

### 2.3 桌面端配置操作（逐步）

**Step 1 — 打开入口**
启动千问办公桌面客户端 → 左侧导航「**扩展**」→「**连接器**」→ 右上角「**+ 添加**」。

**Step 2A — 粘贴 JSON 配置**（推荐，一次性把所有字段带上）

```jsonc
{
  "mcpServers": {
    "my-robot": {
      "type": "streamable-http",
      "url": "https://your-host.example.com/mcp",
      "headers": {
        "Authorization": "Bearer <你的令牌>"
      }
    }
  }
}
```

STDIO 类型的等价写法：

```jsonc
{
  "mcpServers": {
    "my-robot-local": {
      "type": "stdio",
      "command": "uvx",
      "args": ["my-robot-mcp"],
      "env": {
        "ROBOT_TOKEN": "<占位，实际值在客户端里填写或走环境变量>"
      }
    }
  }
}
```

**Step 2B — 手动填写配置**
「+ 添加」→「手动填写配置」→ 先选**服务器类型**：

- 选 `Streamable HTTP / SSE` → 填「服务器名称」「服务器地址」，可选加 Headers（用于认证，如 `Authorization: Bearer your-token`）。
- 选 `STDIO` → 填「服务器名称」「命令」（如 `npx -y @modelcontextprotocol/server-filesystem`），可选加环境变量（适合放 API Key、Access Token）。

官方对两种方式的说法是"效果一致，选择方便的即可"；差别在于粘贴 JSON 会自动解析全部字段，手动填需要逐项录入但更灵活。

**Step 3 — 确认生效**
到「连接器」→「**已安装**」选项卡，在「**自定义**」区域找到你的服务：

- 开关：启用 / 禁用
- 展开：查看该服务注册上来的工具列表（**这是验证接入成功最直接的标志**——能看到 tool 说明 AI 就已经认识它了）
- 编辑 / 删除图标：改配置或移除

**Step 4 — 新建对话测试**
> 官方明确：**刚开启或关闭连接器后，需要新建一个对话任务才能生效，不要在原对话里追问。** 这是最常见的"配好了但说找不到工具"的原因。

### 2.4 端选择差异（重要）

从官方文档目前覆盖来看，**自定义 MCP 服务的配置入口描述在桌面端文档下**（`docs/features/connectors` 归在"桌面端核心功能"目录中）。网页端的能力面较小。若你只在网页版工作，先确认对应入口是否开放，必要时装桌面端。

## 三、辅助路径：技能 / 专家套件 / IM 频道各自的用武之地

MCP 只解决"能不能调到你的接口"。下面这几条是配合用的，不是替代。

### 3.1 技能（Skill）——把你的"方法"教给千问办公

技能打包的是**工作说明书 + 所需材料**，不是代码接口。适合的场景：你希望千问办公每次调用你的 MCP 工具时用同一套固定流程、固定口径。官方建议是把跑通一次的 Prompt 沉淀成 Skill，避免每次重新描述。

- 支持自定义创建、上传、分享；也有公开技能市场可直接安装
- 参考：https://qwenwork.cn/docs/features/skills

**组合建议**：`MCP 连接器`提供能力 + `Skill`固化用法 + `定时任务`让它周期自动跑。这是官方推荐的完整闭环。

### 3.2 IM 频道——解决你说的"远程发消息"

如果你的诉求是"人在外面，用手机指挥自己的电脑"，官方给的正是这套组合，不需要你自己写机器人：

- 在桌面端「IM 频道」→「钉钉」卡片 → **配置** → 扫码绑定（会自动注册/绑定应用）
- 准入策略二选一：**开放模式**（所有人/群可直接对话）／**配对模式**（需你在"配对管理"里点允许，以会话为单位）
- **任务绑定（远程接管）**：在任意已连 IM 会话里发 `/bind` 查看桌面端任务列表，回复 `/bind 1` 即可把手机聊天窗口接到某个正在跑的桌面任务上，之后手机发的消息直接进该任务、任务输出实时同步回手机；`/unbind` 解除
- 同样支持的频道：飞书、Lark（扫码自动创建应用）、微信、企业微信（扫码或手动填 Bot ID + Secret）、Slack（Bot Token + App-Level Token）、WhatsApp

支持的消息类型：文本、图片（OCR/换背景等）、文件（PDF/Excel/PPT/Word/CSV/TXT）、语音、合并转发、图+文组合。连续多条消息按顺序处理，不丢不乱。

参考：https://qwenwork.cn/docs/desktop/im-channels

### 3.3 企业治理（团队/公司场景必须看）

如果你不是个人自用，以下能力会显著影响接入能否落地：

| 能力 | 作用 | 文档 |
|---|---|---|
| **AI 资产 - 连接器管理** | 管理员集中维护企业连接器、凭据与开放范围，并可**限制成员自行添加连接器**（你的 MCP 可能被策略挡掉，或反过来需要管控别人加的 MCP） | https://qwenwork.cn/docs/enterprise-ultimate/ai-assets/connectors |
| **开放平台 - 创建连接器 API** | 用接口批量注册连接器，适合把接入流程集成进企业自己的发布流水线 | https://docs.qwenwork.cn/developer/premium/create-connector |
| **应用授权 / API Key** | 企业自建服务通过管理接口访问千问办公（这是"管理后台自动化"，不是让 AI 调你的机器人） | https://qwenwork.cn/docs/enterprise-ultimate/open-platform/app-authorization |
| **模型 BYOK** | 自带模型密钥，把机器人用的模型侧也统一到企业账号 | https://docs.qwenwork.cn/developer/premium/extension-integration-model-byok-search |
| **PrivateLink 私网链接** | 面向"终端无法访问公网 / 应用无法提供公网服务"两种网络受限场景，让内网 MCP 服务不必暴露公网 | https://qwenwork.cn/docs/enterprise/premium/private-link |
| **Hooks 规则** | 在指定 Agent 事件发生时回调你的 HTTP 服务，可用于审批拦截、审计上报、执行前校验 | https://qwenwork.cn/docs/developer/premium/guide-hooks |

> **PrivateLink 这一条值得特别注意**：它官方描述就是解决"用户应用无法提供公网服务"的问题。如果你的合规要求禁止把机器人暴露到公网，但又要让千问办公调用，企业旗舰版 + PrivateLink 是正规解法，优于自建隧道。

## 四、按你的机器人形态选路

| 你的机器人现在的样子 | 推荐路径 | 注意点 |
|---|---|---|
| 已经是标准 MCP server，有 Streamable HTTP / SSE URL | 连接器 → 粘贴 JSON，`type: streamable-http` | 务必加 Bearer 认证；建议限制来源 IP；新建对话生效 |
| 已经是标准 MCP server，只有本地命令能启动 | 连接器 → STDIO 类型 | 零公网暴露，最省事；需本机装好 Node/Python 运行环境 |
| 部署在本地、只有 HTTP API，没有公网 IP | **首选 STDIO 包一层**；或 Remote MC 适配器走 `localhost` | 桌面端在你机器上，可通过本地进程/本地地址触达，不需要公网 |
| 部署在本地、有公网 API，但没有 MCP | 先用官方 SDK / fastmcp 包一层 MCP 适配层 | 每个 tool 要有清晰 description，AI 靠它决定何时调用 |
| 想让别人也能用上 | 技能 / 专家套件上传到技能市场，或走企业私有市场 | 需过上架审批，技能/套件/连接器都有对应的 review 接口 |
| 希望手机随时指挥电脑上的它 | MCP 连接器（能力）+ IM 频道（通道）+ `/bind`（接管任务） | IM 频道无法挂你自己的机器人，只能驱动千问办公 |

## 五、上线前检查清单

**协议与配置**
- [ ] 确认传输类型三选一已实现（Streamable HTTP / SSE / STDIO），而非裸 REST
- [ ] 每个 tool 都有准确的 `description` 与参数 schema —— 这直接决定 AI 会不会在正确的时机调用它
- [ ] 认证走 Header / 环境变量，**不要把长效密钥写死在 URL 里**（URL 可能进日志）
- [ ] 配置保存后**新建对话任务**再测试
- [ ] 「已安装 → 自定义」里能展开看到工具列表

**安全（把机器人接入 AI 执行链路，这一节不要省）**
- [ ] **最小权限**：MCP tool 只暴露必要操作。不要把"任意 SQL""任意 shell""任意文件读写"直接做成一个 tool —— 这类通配工具一旦被模型误调用，等价于把机器根权限交给 Prompt
- [ ] **默认拒绝 + 白名单**：破坏性动作（删除、对外发送、付款、生产写操作）单独设审批或强制二次确认，不放进自动调用范围
- [ ] **提示词注入防线**：你的 tool 返回的内容（网页文本、DB 记录、日志）会重新进入模型上下文。规则：外部内容只作数据，绝不可当指令；tool 侧对参数做严格格式校验，不接受任何形式的"指令式字符串"
- [ ] **身份绑定**：远程型服务要校验调用方 token 且区分用户身份，避免同一个 token 被复用时越权
- [ ] **审计留痕**：企业侧开启日志审计（AI 日志按对话轮次记录调用了哪些连接器/技能/套件），并保留服务端自己的调用日志
- [ ] **凭据轮换**：Bearer token 定期轮换；发现异常调用可立刻在「已安装」里关闭开关（关开关即止血，比删配置快）

**运维**
- [ ] 明确超时预期：官方说明 MCP 响应时间取决于服务提供方，若持续超时应检查网络或联系服务方
- [ ] 服务不可用时的降级：AI 会在调用失败后自行解释，因此建议你的服务返回明确错误信息而不是超时，避免出现误导性结论
- [ ] 版本变更先在测试服务上验证，接口破坏性改动会让已固化的 Skill 全部失效

## 六、常见问题排查

| 症状 | 原因与处理 |
|---|---|
| 配好了但对话里提示"找不到相关工具" | **新建一个对话任务**（官方明确）；开关已打开；展开确认工具列表非空 |
| MCP 不工作、调用无响应 | 依次检查：①配置/URL 复制完整、格式正确 ②网络可达（部分 MCP 需特定网络环境）③是否还需额外授权或登录 ④删除该服务后重新添加 |
| 调用有延迟 | 属服务提供方特性；持续超时则查网络或找服务方 |
| STDIO 类型加上没动静 | 命令能在本机独立跑通吗？运行环境（Node/Python）装了吗？环境变量是否填全？ |
| 遇到验证码/扫码 | 千问办公无法自动通过复杂验证码、短信验证、扫码登录；需你手动接管，之后在已登录状态下继续 |
| 浏览器操作慢 | 浏览器连接需实时截屏与元素分析，比纯对话慢属正常；大任务建议 Prompt 分步描述 |
| 企业成员加不了连接器 | 可能被管理员的连接器访问策略/开放策略限制，联系企业管理员 |

## 七、最小落地示例

一个把本地 HTTP 机器人接进千问办公的 Python 适配层骨架（FastMCP 系），供参考：

```python
# mcp_server.py — 暴露成本地 STDIO 服务
# 让千问办公通过 STDIO 调用你原本只有 REST 接口的机器人
from fastmcp import FastMCP
import httpx, os

mcp = FastMCP("my-robot")
BASE = os.environ["ROBOT_BASE"]      # 例：http://127.0.0.1:8080
TOKEN = os.environ["ROBOT_TOKEN"]

@mcp.tool
def robot_ask(question: str) -> str:
    """向本地 AI 机器人提问，返回它的回答。适合需要机器人专属知识时使用。"""
    r = httpx.post(f"{BASE}/ask",
                   json={"q": question},
                   headers={"Authorization": f"Bearer {TOKEN}"},
                   timeout=30)
    r.raise_for_status()
    return r.json()["answer"]

if __name__ == "__main__":
    mcp.run()          # 默认 STDIO 传输
```

然后在千问办公「扩展 → 连接器 → + 添加 → 粘贴 JSON 配置」导入：

```jsonc
{
  "mcpServers": {
    "my-robot": {
      "type": "stdio",
      "command": "python",
      "args": ["mcp_server.py"],
      "env": { "ROBOT_BASE": "http://127.0.0.1:8080", "ROBOT_TOKEN": "" }
    }
  }
}
```

> 注意：`description` 是 AI 判断"何时该调用"的唯一依据，务必写清用途和边界，不要只重复函数名。
