## 3. 修订项

### 分派 Stage 2/3 之前

#### F1.（高）招呼语改由平台发送后，缺少"同步"与"核验"机制

R12 改为由平台自动发送你在平台里设置的招呼语，这个方向是对的。但带来两个问题，设计里都没有处理：

1. **FR5.3 的前提条件无法实现。** FR5.3 规定"已定稿但未同步到平台设置时，投递任务不启动"，可软件无从知道你是否已同步。设计文档、开发文档、验收文档里检索"同步"，都没有对应的机制。
2. **会误判每个新会话为"人工接管"。** 设计 §8.1 L410 的人工接管检测，是把我方发出的消息和 `send_intents` 的 `payload_digest` 做比对。现在招呼语的 `payload_digest` 来自控制台模板，而实际发出的是平台里设置的文本：
   - 两者只要有一点不同（你没粘贴、改过一个字，或平台对文本做了规范化），每个新会话都会因为"出现匹配不上的我方消息"被判为人工接管；
   - 结果是自动回复整体失效，而且不会有任何告警。

**建议**：

- **控制台确认**：招呼语工作台增加"已同步到平台"的确认，和模板版本绑定；模板一旦修改，确认自动失效。FR5.3 的启动前置条件改为检查这项确认。
- **运行时核验**：正式运行时，每天第一次 `send_greeting` 成功后，读取该会话中我方的第一条消息，和当前模板做归一化比较（去掉空白和标点差异）。
  - 不一致 → 暂停投递 + 新增中级事件 `GREETING_MISMATCH`，提示"平台招呼语与控制台模板不一致"；
  - 这条消息**不触发人工接管**。
- **匹配规则**：招呼语类的发送意图，改为按"会话关联的岗位 + 时间窗口"匹配，不再按文本摘要匹配。回复和简历仍按摘要匹配。
- **试运行的限制**：试运行不点击，无法核验，所以第一个正式运行日的首次投递就是核验点。这一点要写进 FR3.9 的放量说明。
- **同步修改**：
  - 设计 §5.5：I2 的匹配说明；I5 增加 `GREETING_MISMATCH`；
  - 开发文档：S2b、S2d、S4c、S6b；
  - 验收文档：新增一项（F9）。

#### F2.（中）§5.5 的缺口与写法错误

- **`EngineCommand` 照抄会报错。** I6 中 `payload` 带默认值，却排在没有默认值的 `req_id`、`issued_at` 前面，Python 定义这个数据类时会直接报错。把 `req_id`、`issued_at` 移到 `payload` 前面，或者都给默认值。
- **缺少的跨 SubStage 接口**（调用方要照着写代码，但签名没写进 §5.5）：

  | 接口 | 提供方 | 调用方 |
  |------|--------|--------|
  | `Gate.can_deliver / can_browse / can_poll` | S2c | S4c、S4d、编排器 |
  | 会话 API：能否自动发送、记录一次自动发送、标记接管、基线过滤 | S2d `session.py` | S4c、S4d |
  | 放量与试运行状态：当前放量标志、是否处于试运行、记录拟发送 | S2d `rampup.py`、`dryrun.py` | S4c、S4d、S5c |
  | 简历解析：`parse_resume` 及其异常 | S3c | S4e |

- **I2 没写清试运行分支。** `begin(..., dry_run=True)` 是直接写入 `skipped_dryrun`、不再调用 `resolve`，还是先写 `pending`？要写明，否则 S2b 和 S4c 会各自理解。
