## 1. 背景与目标

用户求职期间需要一款本地运行的 Python 软件，代替人工在 Boss直聘完成：职位筛选与自动投递、HR 消息 AI 辅助回复、分级告警通知。v1.0.0 交付：Windows 本机稳定运行的本地 Web 控制台 + 自动化引擎 + Mock 模拟测试环境（真实站点仅只读验证），并为多招聘站点扩展预留 `SiteAdapter` 接口。

**本设计的三条硬约束**（全文档生效）：

1. **保守熔断优先**：任何不确定状态（登录失效/风控/适配器失效/发送结果未知）一律停、报、等人，绝不自动重试发送动作 [NFR2, B4]；
2. **真实站点隔离**：开发期全部行为针对 MockSiteAdapter；真实站点操作集中在 ZhipinAdapter，且默认只在 TEST3 试运行启用 [Q18]；
3. **零上下文可开发**：任何模块的契约（数据结构、错误、路径）在本文档或其引用的需求文档中完整定义，SubAgent 不需要对话历史。

## 2. 总体架构（四层）

```text
┌─────────────────────────────────────────────────────────┐
│  L4 控制台层  console/   FastAPI(127.0.0.1:8000) + 静态页面 │
│      ▲ 只读 DB / 队列指令；不直接触碰浏览器                  │
├─────────────────────────────────────────────────────────┤
│  L3 核心调度层 core/    orchestrator(单执行者队列)          │
│      scheduler(时段/频率)  delivery(投递流水线)             │
│      messenger(轮询/路由)  session(会话状态)                │
│      state_machine(发送状态机)  dryrun(试运行/放量)          │
├─────────────────────────────────────────────────────────┤
│  L2 站点适配层 adapters/  SiteAdapter 抽象                  │
│      ZhipinAdapter（真实） │ MockSiteAdapter（开发/测试）    │
├─────────────────────────────────────────────────────────┤
│  L1 浏览器会话层 browser/  可插拔策略 [Q18]                  │
│      S1 PlaywrightCdpStrategy（默认，channel="chrome"）     │
│      S2 DrissionPageTakeoverStrategy（占位，v1 不实现）     │
│      S3 DesktopInputStrategy（占位，v1 不实现）             │
└─────────────────────────────────────────────────────────┘
        横切：ai/（评估·分类·回复·护栏）  notify/（分级通知）
              db/（SQLite）  config（YAML）  resume/（解析）
```

- **依赖规则**：L3 只 import `adapters.base`（抽象），不 import 任何具体站点 [FR10.2]；adapters 通过注册表 `create_adapter(site_id, strategy, config)` 装配；ai/notify/db 被各层调用但不反向依赖。
- **进程模型**：单进程双线程——主线程跑引擎（orchestrator 循环），副线程跑 FastAPI(uvicorn)。两线程只通过 SQLite + 线程安全指令队列通信，共享对象仅限不可变配置快照。
- **单实例锁**：启动时创建 `%LOCALAPPDATA%/job_agent/instance.lock`（独占文件句柄），已存在则报错退出 [B5]。

## 5. 领域模型与 SiteAdapter 契约

### 5.1 领域模型（models.py，全部 dataclass/Pydantic）

```python
class JobRef:            # 列表级
    job_id: str          # 平台岗位 ID（去重与缓存键）
    title: str
    company_name: str
    company_key: str     # 去重键：优先平台公司/品牌 ID，后备规范化公司名 [B9]
    salary_text: str     # 原文，如 "20-30K·14薪"
    salary_min_k: int | None   # 解析后月薪下限（千），面议=None
    salary_max_k: int | None
    tags: list[str]      # 列表标签（含福利标签）
    list_snippet: str    # 列表页摘要

class JobDetail(JobRef):
    jd_text: str         # 职位描述全文
    experience: str      # 经验要求原文
    company_scale: str   # 公司规模原文
    detail_url: str

class Conversation:
    conv_id: str
    peer_name: str       # HR 名称（入库脱敏由导出层负责）
    job_ref: JobRef | None    # 关联岗位 [B8]；None=取不到
    last_message_at: datetime
    unread: int

class MsgType(str, Enum):
    TEXT / IMAGE / VOICE / FILE / JOB_CARD / RESUME_REQUEST_CARD \
    / CONTACT_REQUEST_CARD / INTERVIEW_CARD / SYSTEM

class Message:
    platform_msg_id: str
    conv_id: str
    direction: Literal["in", "out"]
    sender: Literal["hr", "me", "system"]
    msg_type: MsgType
    text: str                     # 多模态时为空或说明
    sent_at: datetime
    is_ours_auto: bool | None     # 【核心层计算，适配器不提供 [G6]】我方消息与 send_intents
                                  # 按 payload_digest + 时间窗(±10min) 匹配；匹配不上=None→按人工消息处理（转人工，保守）

class SendOutcome(str, Enum): SENT / FAILED / UNKNOWN / PENDING / SKIPPED_DRYRUN
```

### 5.2 SiteAdapter 抽象（adapters/base.py）

```python
class LoginState(Enum): LOGGED_IN / LOGGED_OUT / UNKNOWN
class RiskSignal(Enum):
    NONE / CAPTCHA / RISK_PAGE / LOGIN_EXPIRED / ADAPTER_BROKEN / PLATFORM_LIMIT / EVICTED / SECURITY_CHECK
    # [B6,B7,G2,H1]；EVICTED=about:blank 或非我方发起跳转；SECURITY_CHECK=URL 含 _security_check
    # 或验证类路径 / 页面出现"安全验证、环境异常、验证码"类文字 / 导航后停留页非目标页连续 2 次

class SiteAdapter(ABC):
    site_id: str
    def check_login_state(self) -> LoginState: ...            # 更名自 ensure_login_state [B8]
    def detect_risk(self) -> RiskSignal: ...
    def search_jobs(self, filters: SearchFilters, page: int) -> list[JobRef]: ...
    def get_job_detail(self, job_id: str) -> JobDetail: ...
    def send_greeting(self, job: JobRef, message: str) -> SendOutcome: ...
    def send_reply(self, conv_id: str, message: str) -> SendOutcome: ...
    def send_resume(self, conv_id: str) -> SendOutcome: ...   # 多份简历时选 config 指定名 [B8]；前置校验：HR 未回复的会话无法发送（R12 实测），不满足时返回 FAILED + 明确原因，不重试
    def list_conversations(self) -> list[Conversation]: ...
    def get_messages(self, conv_id: str, since: datetime | None) -> list[Message]: ...
    def get_conversation_job(self, conv_id: str) -> JobRef | None: ...
    def snapshot_conversation_baseline(self) -> int: ...       # 返回基线会话数 [B3]
```

- **全部同步方法**（引擎单线程串行调用；Playwright 同步 API 匹配）。
- **错误分类**（base.py 定义，调用方按类处理）：

| 异常 | 含义 | 调用方行为 |
|------|------|-----------|
| `LoginRequiredError` | 登录失效 | 熔断：停全部任务+高告警 [FR1.3] |
| `RiskDetectedError(signal)` | 验证码/风控页 | 熔断：暂停+高告警 [FR1.4] |
| `AdapterBrokenError` | 关键元素连续 N 次（默认 3，可配）定位失败 [B7] | 熔断：暂停+高告警 |
| `PlatformLimitError` | 平台"今日沟通达上限"类提示 [B6] | 当日停止投递；消息处理照常；中级通知 |
| `TransientError` | 网络抖动等临时错误 | 指数退避重试 ≤2 次，仍失败按 FAILED 落库 |
| 其他 `AdapterError` | 未分类 | 当前职位/会话标记失败跳过，循环继续 [NFR2] |

### 5.3 浏览器会话层（browser/）[G4 修订]

- **策略接口**：`BrowserSession` 暴露 Playwright 同步 Page 级原语（goto/wait_for/click/query/scroll/screenshot + persistent profile 管理）。**该接口仅供 S1a/S1b（同属 CDP、API 兼容）使用**；浏览器扩展路线作为独立 SiteAdapter（`ZhipinExtensionAdapter`）注册，不经 BrowserSession；半自动兜底时发送动作由用户完成，BrowserSession 仅承担读取。
- **S1a 实现**（原 playwright 驱动）：**已被实验排除，代码不进产品**（实验脚本仅在 `private/survey/` 留档）[K2]。
- **S1b 实现**（browser/patchright_session.py，**正式定型路线**——2026-11-07 第二轮 X4 按产品形态通过 [M4 条件达成，v13]）：以 `patchright`（1.64.4，Apache-2.0，Playwright drop-in）为驱动；官方 Best Practice：`launch_persistent_context(channel=config.channel, user_data_dir=.browser_profile, headless=False, no_viewport=True)`，**Patchright 默认启动参数**，不加自定义 headers/UA、无注入。依赖锁定 `patchright==1.64.4`（console API 不可用——本项目不依赖 console 监听）。
- **Chrome 版本联动降档** [V9]：启动时记录 Chrome 版本；检测到主版本变化后的第一次运行自动采用试运行第 1 档浏览上限（15/时·60/天）+ 中级通知；运行 30 分钟无风控信号自动恢复配置值。
- **登录模式（M3/G5）**：引擎外由 `POST /browser/login-mode` 以普通方式启动 `chrome.exe --user-data-dir=<.browser_profile>`（无调试端口/管道），用户扫码登录并**关闭窗口后**引擎方可启动；登录窗口打开期间引擎启动被拒绝（同一 profile 不能双进程占用，提示"请先关闭登录窗口"）；FR1.3 登录失效恢复同走此模式。
- **单执行者队列**（core/orchestrator.py）[B5]：所有站点操作进同一优先级队列串行执行，优先级 `登录/风控检测 > 回复发送 > 投递 > 浏览采集`；队列积压超 30s 记 WARNING。回复操作同样执行 8-20s 随机节流（与投递共用拟人节奏参数，设计不区分）。
- **驱逐与拦截处理** [G2, H1]：URL 变为 `about:blank` 或非我方发起的异常跳转 → `RiskSignal.EVICTED`；URL 含 `_security_check`/验证类路径、页面出现"安全验证/环境异常/验证码"文字、导航后停留页非目标页连续 2 次 → `RiskSignal.SECURITY_CHECK`——两者均按风控熔断（暂停全部任务 + 高级告警），**禁止自动重新导航**；**内容级健康检查**：页面加载成功但预期内容缺失（搜索页零职位卡、详情页无 JD 正文等）计入 AdapterBroken 连续失败计数 [B7]；`TargetClosedError` 后自动重建浏览器**最多 1 次/小时**，关闭前出现过 EVICTED/SECURITY_CHECK 则**不重建**、直接暂停等人工处理；控制台提供"重新拉起浏览器"按钮。
- **版本记录** [G4]：启动时将本机 Chrome 版本写入日志（channel="chrome" 使用本机 Chrome，约每 4 周自动升级；升级后首次运行异常可借日志快速定位）。

## 7. 投递流水线（core/delivery.py）

执行顺序 [B9]（每步失败按第 5.2 节错误表处理，单职位失败不中断循环）：

```text
[调度闸门] 运行时段(工作日=周一~五) ∧ 投递频率窗口可用 ∧ 浏览上限未达 ∧ 无熔断 ∧ 前置条件满足
 1 search_jobs(filters, page)                     # 列表级；翻页计入 search_page_hourly [G3]
 2 列表过滤: 去重(company_key) ∧ 公司黑名单/排除关键词(公司名)；匿名公司卡跳过
   （skipped_by=anonymous_company，可配详情级补判 [v13]；薪资过滤已移除 [R13]）
 3 get_job_detail(job_id)                          # 详情级；成功后 detail 浏览计数+1（不分 dry_run）[G3]
 4 详情过滤: 排除关键词组(JD正文+福利标签) ∧ 经验要求规则
 5 evaluations 缓存命中? → 复用；否则 AI 评估(§9.1) 并入缓存
 6 判定: verdict != skip ∧ score >= min_score(矛盾从保守) [FR4.2]
 7 dry_run? → send_intents(SKIPPED_DRYRUN)+applications(dry_run=1) → 下一职位
 8 send_intents(pending) → send_greeting（=点击「立即沟通」，平台自动发已同步模板 [R12]）→ sent/failed
 9 applications 落库 + companies 去重登记
10 随机延时 8-20s → 下一职位
```

- **薪资语义**：**已废止 [R13]**——DOM 层薪资全线字体加密（列表 `job-salary` 与详情薪资节点均无明文，v13 实测），v1 不做任何薪资规则处理；目标薪资不注入 AI 偏好，JD 文本内薪资仅作自然上下文。
- **被动招呼计数** [D0]：FR3.7 的被动招呼语发送同样计入小时/日投递限额。
- **平台限额** [B6]：`PlatformLimitError` → `run_state.platform_limit_date=当日`，当日跳过投递步，其余照常。
- **浏览上限** [G3]：`browse_limits`（详情 40/时、200/天，翻页 30/时，X4 校准后修订）任一达到 → 停止对应动作（达到详情日限则当日不再打开新 JD，存量流程走完）+ 中级通知；计数不分 dry_run（浏览即暴露）。配置页提示：按 200 详情/天与评估通过率推算，每日实际投递量可能低于 100——安全优先于投递量。

## 8. 消息轮询与路由（core/messenger.py）

轮询循环：时段闸门（默认与投递共用，可独立配置 [P1]）→ `list_conversations()` → 对每个有新消息的会话 `get_messages(since)` → 逐条路由 → 生成动作。

**路由优先级表**（从高到低，命中即止；一条消息多意图按最高风险处理）[B1]：

| 序 | 消息形态 | 类别 category | 动作 |
|----|----------|--------------|------|
| 1 | SYSTEM（已读/系统通知） | system | 不回复；供 FR8.2 状态推断（如"已读"→已读不回） |
| 2 | CONTACT_REQUEST_CARD（交换微信/电话） | contact_request | **永不自动处理**：进待发箱 + 中级告警 |
| 3 | RESUME_REQUEST_CARD（索要简历卡片/文字） | resume_request | FR3.8 开 → 附件简历自动投（§8.1 计数）；关 → 待发箱 + 中级告警 |
| 4 | INTERVIEW_CARD / AI 分类=面试邀约 | interview_invite | 待发箱(草拟确认) + 中级告警 [FR7.2] |
| 5 | IMAGE/VOICE/FILE/JOB_CARD | multimodal | 待发箱(人工) + 中级告警，AI 不解读 [A2] |
| 6 | 文本 → AI 分类 | low_risk / key / positive_response / no_reply | §8.2 |

- AI 分类失败或输出解析失败 → 按 `key` 处理（进待发箱）[B1]。
- **`no_reply` 类** [B2]：纯寒暄/收到/表情（分类 prompt 中定义）；标记已处理，不发送、不计数、不告警。

### 8.1 会话计数与转人工

- `auto_sent_count`：主动/被动招呼语 + 自动回复消息，每条 +1；达 `auto_reply_limit`（默认 2，下限校验 1）→ 会话 `manual_takeover=1` + 中级告警"会话达自动上限"。
- `resume_sent_count`：附件简历自动投递独立计数，每会话上限 1 [A2]；投递失败不重试（NFR2）。
- **手动接管检测** [B3, G6]：核心层把 direction=out 的我方消息与 `send_intents`（payload_digest + ±10min 窗口）匹配；出现**匹配不上**的我方消息（用户在 App/网页手回）→ `manual_takeover=1`（不再自动发送，AI 可继续草拟，见 §8.3）。
- **首次运行基线** [B3]：首次启动 `snapshot_conversation_baseline()`，基线内会话 `is_baseline=1` 不参与自动化；基线会话公司是否导入去重名单 = 配置项（默认导入）。dry_run 关闭时重拍基线 [N2]。

### 8.2 回复生成与发送

- `low_risk`：AI 生成 → **护栏检查**（§9.4）→ 通过 → 单执行者队列发送（节流）；不通过 → 待发箱。
- `key`（薪资/到岗/面试时间等）与 `interview_invite`：AI 草拟 → 待发箱 + 按级告警。
- `positive_response`（FR3.8 关闭态）：待发箱 + 中级告警。

### 8.3 待发箱规则（B10）

- 用户确认发送 **不计入** 自动发送计数（人工行为）；
- 会话转人工后：新消息仍生成草稿进待发箱（用户决定发否），不再自动发送；
- **草稿过期**：待发箱条目存在期间该会话再来新消息 → 条目标记 `stale`，确认页提示"有新消息，建议重新生成"；
- **超时提醒**：每轮轮询扫描一次，所有滞留 >`outbox_timeout_min` 的未处理条目**合并为一条高级告警**（每条目只提醒一次）[FR6.4, s6]；时段外到期的条目在下一轮轮询时并入扫描（不即时唤醒）[B10]。

## 9. AI 层设计（ai/）

### 9.1 匹配评估（evaluate.py）

- 输入：JobDetail.jd_text + 结构化简历（§9.5）+ `preferences`（v1 恒空 [V2-7]）；输出 JSON：`{"score":0-100,"verdict":"recommend|neutral|skip","reason":"..."}`。
- 解析：提取 JSON（代码块/裸 JSON 兜底）→ Pydantic 校验 → 失败/超时 = 该职位跳过（宁缺毋滥）[FR4.2, B13]。
- `skipped_by` 留痕：`low_score / verdict_skip / ai_error / preference_hard`（最后者 v2 启用）。
- **日预算** [B13]：`ai.daily_budget_calls`（默认 1000）计评估+分类+生成总调用；达限 → 停止评估与自动回复（存量草拟转人工）+ 中级通知。

### 9.2 消息分类（classify.py）

输入：最近 N=10 条会话消息 + 分类说明；输出 JSON：`{"category":"low_risk|key|positive_response|no_reply","reason":"..."}`（卡片类已在路由层拦截，不进 AI）。注入测试夹具进 TEST1 [B12]。

### 9.3 回复与招呼语生成（reply.py / greeting.py）

- system prompt 固定包含：结构化简历事实 + 求职目标 + **行为红线**（不编造经历、不承诺薪资数字/具体时间、不主动留联系方式）[FR6.2, NFR1]。
- 不可信文本（JD/HR 消息）置于数据块，与指令用分隔标记隔离 [B12]。
- 招呼语工作台：主动/被动两模板各出 3 候选，用户编辑定稿 1 条入 `greeting_templates(is_current)` [FR5]。

### 9.4 发送护栏（reply.py 内 guard 函数，纯规则可测）

自动发送前检查，命中任一 → 降级待发箱并标注原因：① 正则命中手机号/邮箱/微信号/QQ号；② 薪资数字承诺（"期望XX k""最低XX"）；③ 具体日期时间承诺（明天/周X/X号+到岗语义）；④ 长度 > 500 字符 [B12]。

### 9.5 简历结构化（resume/parser.py）

pypdf 提取全文 → 文本 < 200 字符判定为扫描件 → 明确报错"图片型 PDF 不支持，请提供文字版" [B15]；AI 结构化为 `{education, experience, skills, projects}` JSON 入 `resume_snapshots`；控制台可查看+手动修正（修正生成新版本）[FR2.5]。给 AI 的简历副本去除联系方式字段 [B12]。

### 10.4 统计口径与状态推断（B16）

**看板指标定义**（GET /stats 实现依据，TEST1 用例来源）：

| 指标 | 分子 / 分母 | 窗口 |
|------|-------------|------|
| 每日投递数 | 当日 `applications(dry_run=0)` 行数 | 自然日 |
| 回复率 | 收到 ≥1 条 HR 回复（direction=in, sender=hr）的投递会话数 / 全部已发送投递数 | 近 7 天 / 30 天（页面可切） |
| 通过率 | 评估判定投递数 / 评估总数（`evaluations` 中 dry_run=0） | 同上；按 `skipped_by` 归因细分（low_score / verdict_skip / ai_error） |
| 匹配度分布 | 已投递岗位 score 直方图（10 分一档） | 同上 |
| 会话状态分布 | conversations 按 FR8.2 状态计数 | 全量 |

**FR8.2 投递情况自动推断规则**（保守，只推断有明确信号的；其余保持"沟通中"）：

| 信号 | 推断状态 |
|------|----------|
| SYSTEM 消息含"已读" | 已读不回 |
| HR 文本命中拒绝关键词（不合适/不匹配/遗憾/另寻） | 明确拒绝 |
| 会话关闭 SYSTEM 信号 | 已关闭 |
| 存在面试邀约且用户确认 | 已面试（用户手动标记为主，此条半自动：提示用户确认） |

手动标记永远优先于自动推断；推断变化写入 msg_routing 留痕。

## 11. 通知系统（notify/）

- **事件类型 → 级别**（FR7.2 权威表，代码为枚举）：

| 级别 | 事件 |
|------|------|
| high（邮件+飞书必推，不受免打扰限制[可配]） | 登录失效、风控/验证码暂停、适配器疑似失效、待发箱超时（合并一条）、浏览器会话丢失、**页面被驱逐（EVICTED）** [G2] |
| medium（飞书默认推，级别可配） | 面试邀约、关键提问待确认、offer 迹象、会话达自动上限、多模态待处理、联系方式交换请求、平台限额触发、AI 预算耗尽、放量期结束 |
| low（飞书可关） | 每日运行摘要（跟投递时段结束 [s1,B11]）、试运行数据就绪 |

- **路由管线**：event → notification_events 落库（全量，永远）→ 级别过滤 → 免打扰（中低延后至结束合并推送，notify_dedup 计数 [B11]）→ 飞书 Webhook（签名）+ SMTP（仅 high）。
- **摘要不补发**：时段结束软件未运行 → 下次启动总览页显示昨日摘要，不推送 [B11]。
- 插件接口 `Notifier.send(event)`；新增渠道纯增量 [FR7.1]。

## 13. 断点续跑与对账（core/state_machine.py + dryrun.py）

- **发送状态机** [B4]：发送前 `send_intents(pending)` → 执行 → `sent/failed`；启动恢复：残留 `pending` → `unknown`，**只对账不重发**；对账任务（低频，每日一次+熔断恢复后）：`list_conversations/get_messages` 取回我方消息，经 §8.1 的 digest 匹配规则 [G6] 核对 `unknown` intents——会话中出现对应消息→`sent`；未出现→保持 `unknown` + WARNING（**仍不重发**）。
- **频率窗口** [B4, G1]：启动时从 `send_intents`（`state IN (pending,sent,unknown,skipped_dryrun)`，不分模式）重算当前小时/日已用额度，不清零。
- **放量期状态机** [N1, G10]：dry_run 由用户关闭 → `ramp_up.remaining_days=3`；每达成一个"有效运行日"（当日发生投递动作；被平台限额/浏览上限拦住的当日不计 [Q20]）减 1；期间日限=ramp_up.daily_limit、低风险自动回复关、FR3.7/3.8 关；归零 → 自动恢复配置值 + 低级通知；用户可随时提前/延长（控制台）。**放量/试运行期间任何风控信号（EVICTED/SECURITY_CHECK/风控页）→ 暂停全部任务 + 高级告警 + 等用户决策**（M5：无自动回退、不自动恢复；半自动不在 v1 范围，需要时 v1.x 立项）。
- **试运行浏览放量档位** [H2]：第 1 个试运行日详情上限 15/时·60/天；每个无风控信号的试运行日翻倍至配置值；任何风控信号 → 回第 1 档 + M5 处置。Chrome 主版本变化联动降档见 §5.3 [V9]。
- **休眠与电源** [B18, G11]：① 运行时段内调用 `SetThreadExecutionState(ES_SYSTEM_REQUIRED)` 防系统休眠，时段结束释放（本机存在电源/显卡驱动故障史，为稳定性刚需 [Q21]）；② 系统时钟跳变检测（单调钟与墙钟偏差 > 5min）→ 恢复任务前先 `check_login_state + detect_risk`。
