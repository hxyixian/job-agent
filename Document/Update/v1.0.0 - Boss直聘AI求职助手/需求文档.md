## 1. 项目背景与目标

用户正在求职（求职方向、目标城市与目标薪资区间属个人信息，以**求职目标配置**指代，具体值仅存于用户本机配置，见第 10 节），需要一款本地运行的 Python 软件代替人工在 Boss直聘（https://www.zhipin.com）完成重复性求职操作：筛选职位、投递沟通、回复 HR 消息，并在关键事件发生时按分级推送告警。软件由 AI 大模型驱动决策（岗位匹配评估、消息分类、回复生成），用户保留最终控制权（职位方向确认、招呼语定稿、关键消息人工确认）。

**v1.0.0 目标**：交付可在用户 Windows 本机稳定运行的本地 Web 控制台应用，实现 Boss直聘自动投递 + AI 辅助回复 + 分级告警通知，通过 SiteAdapter 接口为后续招聘站点预留扩展点。

## 2. 用户与运行环境

- 单用户本地使用；用户具备开发背景（可编辑 YAML、查日志）。
- Windows 本机，Python 3.10+；软件驱动本地**真实浏览器**会话（默认 Chrome，可切 Edge）操作 Boss直聘；控制台经浏览器访问 `http://localhost:8000`（仅本机）。
- 账号前提：用户持有 Boss直聘账号并自行扫码登录；持有至少一家 OpenAI 兼容 AI API Key（DeepSeek / GLM / 通义 / OpenAI）；持有飞书账号（接收告警）。

## 3. 术语

- **招呼语**：投递时发送给 HR 的首条固定模板消息（AI 出候选、用户定稿）。分**主动招呼语**（我方主动投递岗位时使用）与**被动招呼语**（HR 主动来询时使用），两套独立模板。
- **附件简历**：用户预先在 Boss直聘账号内手动上传的简历文件（站内附件简历）；Agent 通过聊天窗口的"发送简历"功能投递，不直接上传本地文件。
- **正向回应**：打招呼后 HR 表现出积极信号的回复（如索要简历、约面试、询问到岗时间等），由 AI 消息分类识别。
- **待发箱**：AI 草拟但需用户确认/编辑/跳过后才能发出的回复队列。
- **会话**：与某一位 HR 的消息往来串；单会话自动发送计数含招呼语。
- **多模态消息**：HR 发来的图片/语音/职位卡片/附件等非纯文本消息。

## 4. 功能需求

### FR1 登录与会话管理（P0）

- FR1.1 Playwright 持久化用户数据目录保存会话；**扫码登录在软件以普通模式（无调试参数、无自动化控制）拉起的浏览器中完成**（M3，2026-11-06），登录后关闭窗口，引擎方可启动；登录失效后的恢复同走此模式。
- FR1.2 登录状态由用户自行管理：Agent 绝不执行任何登录操作。
- FR1.3 每轮任务前及循环中周期检测登录态；失效（出现登录页/扫码页）时立即终止全部自动任务，并：a) 推送高风险告警；b) 控制台红色横幅；c) 状态落日志。用户手动重登后可手动恢复。
- FR1.4 `detect_risk()` 检测验证码/风控页 → 自动暂停全部任务 + 高风险告警，人工处理后恢复；**页面被强制驱逐**（URL 变为 about:blank 或非我方发起的异常跳转）视同风控信号（EVICTED）熔断处理，**禁止自动重新导航**（G2）；**站内安全拦截形态**（SECURITY_CHECK，H1）——URL 含 `_security_check` 或验证类路径、页面出现"安全验证/环境异常/验证码"类文字、导航后停留页非目标页连续 2 次——同样熔断；页面加载成功但预期内容缺失（如搜索页无职位卡、详情页无 JD 正文）计入适配器失效判定（B7 连续失败计数，H1）。

### FR2 简历与职位方向配置（简历驱动，P0）

- FR2.1 上传简历 PDF → 解析为结构化文本（教育/经历/技能/项目）。
- FR2.2 AI 分析简历 → 自动生成建议职位方向（多组搜索关键词 + 每组依据说明），用户确认/编辑/增删后存入配置。
- FR2.3 简历可随时更换并重新生成方向；方向随时可手动编辑（生成不是唯一入口）；更换简历时提示重新生成职位方向与招呼语候选（提示不强制失效）。
- FR2.4 简历结构化文本作为 AI 上下文（招呼语候选、回复生成、匹配评估的事实依据）。
- FR2.5 解析后的结构化文本可在控制台查看与手动修正，修正结果作为后续 AI 上下文的事实来源（防止 PDF 解析错误传染各 AI 环节）。

### FR3 职位筛选与自动投递（P0）

- FR3.1 筛选条件可配置：城市、公司规模、经验要求、关键词组（来自 FR2.2）；城市默认值取**求职目标配置**（首次使用引导设置，属个人信息，不入公开文档）。**薪资维度 v1 完全不做**（R13：DOM 层薪资全线字体加密无明文 [v13 实测]，2026-11-07 用户决策 D）——不筛选、不注入 AI 偏好；JD 文本中自然出现的薪资信息仅作为 AI 评估的普通上下文，软件不做任何薪资规则处理。
- FR3.2 排除项可选开关（外包公司/猎头职位/培训实习兼职），默认全关；排除规则按**"预置组 + 自定义组"**组织，v1 仅启用预置组（自定义组 V2-7 开放），架构可扩展；外包/猎头判定为**启发式**（可配置关键词列表 + 公司黑名单），存在误杀可能，配置页注明。
- FR3.3 投递主流程：搜索 → 规则筛选与排除 → 抓取 JD → AI 匹配评估（FR4）→ 通过 → **点击「立即沟通」**（平台自动发送已同步至平台设置的主动招呼语，R12）→ 记录入库（FR8）。
- FR3.4 四级控制（均可配置）：操作间随机延时 + 每小时投递上限（默认 25，滑动 60 分钟窗口）+ 每日投递上限（默认 100）+ **浏览上限**（职位详情默认 40/小时、200/天；搜索翻页默认 30/小时——初值保守，X4/试运行校准后修订）；任一达到即停止对应动作并通知。**操作级最小间隔**（H2，独立于随机延时之外的下限约束）：打开职位详情 ≥30 秒、搜索列表加载/翻页/滚动加载 ≥30 秒（依据同类项目实测 code 37 数据与本项目 X4 实测节奏 41-53s，试运行校准）。限额计数**不区分试运行/正式运行**（衡量账号暴露，G1）；配置页提示：按浏览上限与评估通过率推算，每日实际投递量可能低于 100（安全优先于投递量，G3）。
- FR3.5 运行时段可配置（初始建议工作日 10:00-16:00），调度器仅在时段内执行，其余休眠；HR 消息轮询/自动回复**默认共用同一时段，可独立配置**；"工作日"指周一至周五，不区分法定节假日/调休（可手动启停）；首次使用引导配置。
- FR3.6 去重：默认同公司投递过一次即永久拉黑；可切换冷却 N 天模式；以数据库记录为准。
- FR3.7 **被动招呼**（默认关闭，用户配置生效）：HR 主动发起会话/询问时，获取该会话关联岗位 → AI 匹配评估（同 FR4 契约）→ 评估通过 → 发送**被动招呼语**（独立模板）并投递**附件简历**。前提：用户已在 Boss直聘站内上传附件简历（手动一次性操作；任一功能开启时，软件启动时提示一次，**不做自动检测**——附件简历准备属求职者自身功课，不由软件兜底）。评估不通过（含无法获取会话关联岗位）或功能关闭时，该会话走 FR6 常规消息分类流程。被动招呼语计入该会话自动发送**消息**计数（FR6.3）；附件简历为**独立计数**（每会话最多自动投递 1 次，不占消息额度，R6/A2）。
- FR3.8 **正向回应自动投递附件简历**（默认关闭，用户配置生效）：主动投递后 HR 出现**正向回应**（如索要简历，由 FR6 消息分类识别）时，自动投递附件简历（附件简历独立计数：每会话最多 1 次，不占 FR6.3 消息额度）。功能关闭时，正向回应消息按关键消息处理：进待发箱 + 中级告警通知用户。前提同 FR3.7。**平台约束（R12 实测）**：HR 回复前无法发送简历——FR3.7（HR 已来询）与 FR3.8（正向回应必在回复后）天然满足前置；实现须做前置校验，不满足时不重试（NFR2）。
- FR3.9 **试运行模式（dry_run）**（首次安装默认开启）：真实执行搜索、规则筛选、JD 抓取、AI 匹配评估、消息轮询、消息分类与回复草拟，但所有 `send_*` 操作（招呼语/回复/附件简历）只记录为"拟发送"，不实际发送；控制台可查看"正式运行将发出什么"清单。试运行产生的真实 JD 抓取与评估记录可导出为 TEST2 夹具与 L1 标注数据（TEST4）。**数据隔离**：拟发送记录单独存放，不进入 FR3.6 去重名单、FR8 投递记录、统计看板与 FR6.3 会话自动发送计数；评估结果缓存（按岗位 ID）试运行与正式运行共用。**频率**：试运行与正式运行使用同一套三级频率控制，拟发送同样计入小时/每日上限。**告警**：登录失效、风控、适配器失效等告警照常推送。**待发箱**：试运行期间只展示草稿，用户确认也不实际发送；需回复 HR 时请直接用 App/网页（人工接管检测识别，B3）。**切换**：关闭试运行时重新拍一次会话基线快照（B3），避免切换瞬间集中触发被动招呼；**招呼语运行时核验（F1）**：试运行期间无法核验平台招呼语，**第一个正式运行日的首次投递即为核验点**（成功后读回该会话我方首条消息与模板归一化比对，不一致 → 暂停投递 + GREETING_MISMATCH 中级告警）。**试运行浏览放量**（H2）：第 1 个试运行日详情上限降至 15/小时·60/天，此后每个无风控信号的试运行日上限翻倍，直至达到配置值；出现任何风控信号（EVICTED/SECURITY_CHECK/风控页）→ **暂停全部任务 + 高级告警 + 等用户决策**（M5：不自动切换模式、不自动恢复），恢复后浏览上限回到第 1 档。首次实投**逐步放量**：试运行经用户确认关闭后，前 **3 个有效运行日**（FR3.5 判定的工作日且当日发生投递动作，被平台限额/浏览上限拦住的当日不计，G10）每日投递上限降至 10、低风险自动回复关闭（全部进待发箱）、FR3.7/FR3.8 自动投递附件简历同样关闭；期满**自动恢复**配置值并推送低级通知，用户可随时手动提前结束或延长放量期；放量参数可配置（§10）；放量期间任何风控信号 → 同 M5 处置（暂停+告警+等决策）。

### FR4 AI 岗位匹配评估（P0）

- FR4.1 JD + 简历结构化文本交 AI 评估，输出 `score(0-100)` / `verdict(recommend|neutral|skip)` / `reason`。评估输入预留 `preferences: list[PreferenceRule]`（每条 = 偏好文本 + 强度 hard/soft，V2-7 使用），v1 恒为空表；验收口径：字段为空时评估行为与不存在该字段完全一致。
- FR4.2 投递判定：`verdict != skip` **且** `score >= min_score` 时投递；`verdict == skip`、`score < min_score` 或调用/解析失败 → 不投（宁缺毋滥）；score 与 verdict 矛盾时按更保守一方处理。`min_score` 可配置，临时默认 60（遗留项 L1 校准后修订）；`neutral` 是否投递为独立开关，**默认允许**。
- FR4.3 评估结果（含跳过原因）入库供查看与统计；支持对评估记录做"愿投/不愿投"人工标注并导出/导入（L1 校准工具，随试运行记录导出）。

### FR5 招呼语工作台（P0）

- FR5.1 AI 按简历亮点 + 目标方向生成候选招呼语，**两套独立模板**：
  - **主动招呼语**：投递岗位时使用的固定模板；
  - **被动招呼语**：HR 主动来询时回复使用的固定模板（FR3.7 开启前必须定稿）。
  - 每套各出 3 条候选，用户编辑定稿 1 条；可随时重新生成/定稿。
- FR5.2 定稿模板的生效机制（R12，依据 2026-11-06 用户实测平台行为）：**主动招呼语由用户粘贴到 Boss直聘「打招呼语」平台设置**——点击"立即沟通"时平台自动发送该预设内容，软件零额外发送；**被动招呼语由软件在会话中直接发送**。主动模板变更时控制台提示同步并提供一键复制。
- FR5.3 **同步确认机制（F1）**：招呼语工作台在主动模板定稿后提供"**已同步到平台设置**"确认勾选（与模板内容哈希绑定）；模板任何修改使确认自动失效。投递任务启动前置条件 = 主动模板已定稿**且**同步确认有效。**运行时核验**：正式运行期间每天第一次 `send_greeting` 成功后，读取该会话我方第一条消息与当前模板做归一化比较（忽略空白与标点差异）——不一致 → 暂停投递 + 中级告警 `GREETING_MISMATCH`（提示"平台招呼语与控制台模板不一致，请重新同步"）；**试运行期间无法核验**（不点击不发送），因此**第一个正式运行日的首次投递即为核验点**（写入 FR3.9 放量说明）。被动招呼语未定稿时被动招呼功能不生效并提示。

### FR6 HR 消息自动回复（P0）

- FR6.1 周期轮询会话列表，识别 HR 新消息：
  - 文本消息按分类处理：**低风险**（寒暄/感谢/确认收到）AI 生成后自动发送；**关键**（薪资/面试时间/到岗时间等）AI 草拟进**待发箱**，等用户确认/编辑/跳过；**正向回应**（索要简历等，见 FR3.8）按该功能开关决定自动投简历或进待发箱；分类规则可配置。
  - **多模态消息**（图片/语音/职位卡片/附件）：AI 不理解、不回复，直接进待发箱并通知用户人工回复或无视。
- FR6.2 AI 回复严格依据简历事实与已配置求职信息，禁止编造经历与承诺。
- FR6.3 单会话自动发送**消息**上限默认 2 条（含主动/被动招呼语，**不含附件简历**），可配 1-N（配置下限校验：小于 1 时按 1 生效并提示）；达到后该会话转全人工模式并通知接管。附件简历自动投递独立计数：每会话最多 1 次，失败不自动重试（NFR2）。
- FR6.4 待发箱超时提醒：滞留超过默认 1 小时（可配）触发**一次高风险**告警（不重复推送；未处理条目在控制台持续可见）。

### FR7 告警分级与通知（P0）

- FR7.1 渠道（v1 仅两条 + 兜底）：
  - **飞书群机器人 Webhook**（主通道）：用户自建群添加自定义机器人（签名校验），填入 Webhook + 密钥；**可配置推送级别**（默认接收高+中级）；
  - **邮件 SMTP**（仅推送高风险级消息）；
  - **控制台通知中心**：全量事件落库，可回溯（永远兜底）。
  - 架构为插件式 Notifier，后续新增渠道纯增量（Server酱/企微等 v1 不做）。
- FR7.2 告警分级：
  - **高**（邮件+飞书必推）：登录失效、风控/验证码暂停、适配器疑似失效、待发箱超时提醒；
  - **中**（默认飞书推送，可配置调整）：面试邀约、关键提问待确认、offer 迹象、会话达自动上限、多模态消息待处理；
  - **低**（仅飞书，可配置关闭）：每日运行摘要、例行统计。
- FR7.3 每日运行摘要：运行时段结束时推送（跟随配置的运行时段结束时间，默认时段对应 16:00），内容为当日投递数/通过率/待处理消息数/会话状态。
- FR7.4 免打扰时段可配置；所有事件同时写入通知中心。

### FR8 投递记录、统计看板与断点续跑（P0）

- FR8.1 SQLite 记录投递：公司、职位、时间、招呼语版本、评估结果、投递情况。
- FR8.2 投递情况状态集（可扩展）：沟通中、已读不回、已面试、明确拒绝、已关闭等；支持手动标记 + 部分自动推断（推断规则设计阶段确定）。
- FR8.3 记录页：按状态筛选 + 公司名关键字搜索；去重判定基于此数据。
- FR8.4 统计看板：每日投递数、回复率、匹配度分布、会话状态统计。
- FR8.5 断点续跑：软件崩溃/重启后基于 SQLite 恢复状态继续运行，已投递的绝不重投。

### FR9 AI 服务配置（P0）

- FR9.1 OpenAI 兼容协议：base_url / api_key / model / temperature 可配置；默认 DeepSeek，支持 GLM/通义/OpenAI 切换。
- FR9.2 配置存 `config.yaml`；控制台提供编辑入口。
- FR9.3 超时 + 指数退避有限重试 + 降级（评估失败→跳过职位；回复生成失败→转待发箱）。
- FR9.4 可选 `proxy` 配置（HTTP 代理，默认留空），供 AI 端点需要代理的场景。

### FR10 多站点扩展接口（P0）

- FR10.1 `SiteAdapter` 抽象基类，接口契约：`ensure_login_state() / search_jobs(filters) / get_job_detail(id) / send_greeting(job, message) / list_conversations() / get_messages(conv_id) / send_reply(conv_id, message) / send_resume(conv_id) / detect_risk() -> RiskSignal`。
- FR10.2 `ZhipinAdapter` 为 v1 唯一实现；核心调度/AI/通知不 import 具体站点（注册机制解耦）。
- FR10.3 v1 不实现其他站点（见 v3 计划）。

### FR11 本地 Web 控制台（P0）

- FR11.1 FastAPI + 浏览器访问 `localhost:8000`，仅本机。
- FR11.2 页面：总览（状态/告警横幅）、简历与职位方向、招呼语工作台、投递任务配置（筛选/排除/频率/时段/去重）、待发箱、投递记录与统计看板、通知配置（FR7）、AI 配置（FR9）、通知中心。
- FR11.3 任务手动启停/暂停/恢复；登录失效与风控暂停状态下的恢复流程有明确提示。

## 5. 非功能需求

- NFR1 安全：登录失效熔断；风控熔断；AI 不自动承诺关键事项；API Key 明文本地存储（风险知悉 R2）。
- NFR2 稳定性：单职位/单会话异常不影响整体循环；异常全落日志与通知中心；不静默重试投递动作。
- NFR3 保守频率：随机延时 + 小时/日上限 + 时段调度，模拟自然使用节奏。
- NFR4 可测试性：核心逻辑与浏览器操作解耦；pytest 覆盖正常 + 边界 + 异常路径；强制启动测试并留证据。
- NFR5 可维护性：模块化（adapters / ai / core / console / notify）；配置与代码分离；分级日志（文件 + 控制台）。
- NFR6 数据：本地 SQLite 单库 + schema 迁移脚本。
- NFR7 软件控制边界：浏览器操作仅经既定浏览器路线（S1a/S1b：Playwright 驱动真实 Chrome；或浏览器扩展 Adapter）进行；通知走 HTTP API；**不采用键鼠模拟操控本机软件**（M2，2026-11-06）。
- NFR8 网络：默认全程无需 VPN/代理；Boss直聘、DeepSeek/GLM/通义、飞书、SMTP 均可国内直连。

## 8. 风险知悉（用户已确认）

| # | 风险 | 应对 |
|---|------|------|
| R1 | 简历全文将发送至所配置的 AI API 提供商（DeepSeek/智谱等） | 功能必然，用户知悉 |
| R2 | API Key 明文存本地配置文件 | 文档提示保管 |
| R3 | Boss直聘改版导致页面元素定位失效 | 检测定位失败→自动暂停+高风险告警，不盲目重试 |
| R4 | localhost 控制台无登录鉴权：本机进程可直接访问 API；用户日常浏览器中的任意网页也能发起跨站请求（CSRF / DNS 重绑定），存在读取数据、篡改配置（如改 AI base_url 窃取简历与 Key）、触发改动接口的风险 | 缓解（设计文档落实）：仅监听 127.0.0.1、Host 头校验、改动类接口要求自定义请求头、敏感字段（API Key/Webhook 密钥/SMTP 授权码）返回打码、GET 无副作用；单人本机场景残余风险低，用户知悉 |
| R5 | 自动化操作存在账号限流/封号风险 | 保守频率 + 熔断机制缓解，无法完全消除（用户已知情接受） |
